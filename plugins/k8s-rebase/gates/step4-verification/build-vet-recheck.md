Run `go build ./...` and `go vet ./...` in each module directory.
Use this exact loop to find modules and skip gitignored vendors:

```bash
for mod_dir in $(find . -name "go.mod" -not -path "*/vendor/*" -exec dirname {} \; | sort); do
  if [[ -d "$mod_dir/vendor" ]] && git check-ignore -q "$mod_dir/vendor" 2>/dev/null; then
    echo "SKIP $mod_dir (vendor is gitignored)"
    continue
  fi
  echo "CHECK $mod_dir"
  (cd "$mod_dir" && go build ./... 2>&1)
  (cd "$mod_dir" && go vet ./... 2>&1)
  # Count errors: non-zero exit from either command = issue found
done
```

Do NOT run build/vet on modules you skipped — their vendor is
stale and will produce false errors. This is a re-run after lint
fixes — it catches issues introduced since Step 1. Use
`podman run --userns=keep-id` with the golang container if the
local Go version is too old. Report total error count from
non-skipped modules only.

VERDICT IS ABSOLUTE — a completed rebase must deliver zero go vet errors:

For each vet error (which cites file:line), determine origin by comparing
the specific line in the base vs result:
  `BASE=$(git merge-base HEAD main 2>/dev/null || git merge-base HEAD master)`
  `base_line=$(git show "$BASE:<file>" 2>/dev/null | sed -n '<line>p')`
  `curr_line=$(sed -n '<line>p' "<file>")`
  If base_line == curr_line (same content): PRE-EXISTING
  If base_line != curr_line or base_line is empty: NEW

Then check if the rebase touched the file:
  `was_modified=$(git diff --name-only "$BASE"..HEAD -- "<file>" | wc -l)`

Verdict by case:
- NEW error: FAIL
- PRE-EXISTING, was_modified>0 (file touched): FAIL — rebase touched this
  file and should have fixed the error; label "PRE-EXISTING (must fix)"
- PRE-EXISTING, was_modified==0 (file untouched): INFO — out of scope for
  this rebase, note with a fix suggestion

Exception: if the error is NEW (base_line is empty or differs from curr_line)
AND the file contains a codegen header (e.g., "Code generated by", "DO NOT EDIT"),
mark as FAIL with explanation (re-run the code generator to regenerate the file).
Pre-existing vet errors in unmodified generated files remain INFO regardless of
codegen header — re-running codegen cannot fix an error that predates the rebase.
